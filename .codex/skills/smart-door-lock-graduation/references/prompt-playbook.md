# Codex 毕设闭环提示词库

按阶段使用这些提示词，并替换方括号中的内容。建议一个聊天只处理一个里程碑或一组紧密相关的故障，不要要求 Codex 一次性实现整个毕设。

## 1 首次项目审计

```text
使用 $smart-door-lock-graduation。

只读检查仓库，并阅读根目录两份项目基线文档。请输出：
1. 当前项目的事实状态；
2. 已确认与未确认的硬件事实；
3. 最近且安全的下一里程碑；
4. 当前缺少的工程文件和交付物；
5. 带可测验收标准的分阶段计划；
6. 可能让后续开发返工的主要风险。

将“已确认事实、合理推断、需要我实测的项目”分开。不要把资料目录中的厂商例程当作本项目自有代码，也不要修改文件。
```

## 2 长期目标

只对耗时较长、可以持续推进的单个里程碑使用，不要用于一行修改：

```text
/goal 完成 STM32F103 智能门锁的[阶段或里程碑]，以[构建输出、主机测试、串口日志、实测数据、重复次数和更新后的追踪矩阵]作为完成证据；保持离线功能、门锁上电安全状态、PA13/PA14 SWD、非阻塞业务逻辑、硬件操作超时和当前范围不被破坏。仅使用本仓库和我明确允许的资料。每次迭代后检查最新证据，修复最小且证据充分的原因，重跑受影响的检查，直到验收标准全部满足。如果必须依赖板卡或未确认的电气事实，停止并报告已完成工作、现有证据、阻塞项以及我需要提供的最小测量或操作。
```

## 3 关闭硬件阶段 0

```text
使用 $smart-door-lock-graduation，只推进阶段 0。检查硬件基线，列出我必须提供的照片、丝印、通断检查、电压测量和电流测量。每一项都写明：接线前提、万用表档位、表笔位置、安全范围、该结果将决定什么。电源和驱动路径未证明安全前，不要让我接真实电磁锁。我返回结果后，更新硬件基线、引脚表、电源预算、BOM 和待确认清单；不得补造缺失数值。
```

## 4 建立仓库骨架

```text
使用 $smart-door-lock-graduation。根据当前“只有文档、尚无自有固件”的状态，建立最小项目管理骨架：README、.gitignore、需求清单、追踪矩阵、接口说明、存储布局、测试计划、测试报告目录和发布说明目录。复用根目录两份基线，不要重复复制大段内容。为最小系统和密码开锁建立首批需求编号及验收标准。不要创建或修改远程仓库。校验文件链接，并报告第一个里程碑门禁。
```

## 5 导入 CubeMX 或 Keil 工程

```text
使用 $smart-door-lock-graduation。检查我刚加入的 CubeMX/Keil 工程，核对 MCU、Flash/RAM、时钟树、Serial Wire、GPIO 安全初始电平、USART1、I2C1、SPI1、USART2、用户代码区、头文件路径和可重复构建输入。除非确有必要，不要改写生成的启动文件或 HAL。输出简短配置审计，修复安全且属于仓库配置的问题，并给出第一次下载、串口和复位测试的精确步骤。
```

## 6 通用里程碑实现

```text
使用 $smart-door-lock-graduation 实现[需求编号和里程碑名称]。

验收标准：
- [可观察行为 1]
- [可观察行为 2]
- [错误或超时行为]
- [资源、次数或稳定性指标]

先只检查相关文件并重述必要假设；再设计最小纵向闭环，完成实现，运行当前环境可用的构建、测试和静态检查，复查边界、超时和状态机安全性，并更新追踪矩阵与测试步骤。由本次修改造成的失败应继续修复并重测。不得声称实物已通过；板卡专属检查标记为 PENDING-HW，并给出精确台架步骤和预期日志。
```

## 7 阶段 1 最小系统

```text
使用 $smart-door-lock-graduation 完成阶段 1：SWD、GPIO 安全初始化、LED 心跳、USART1 结构化启动日志、OLED 启动画面和状态页。OLED 通过独立驱动接口访问，OLED 缺失时系统不得卡死。有真实工具链时完成真实构建；没有时明确缺少的命令或工具。提供一小时稳定性测试步骤和串口证据格式。此阶段不要加入键盘、EEPROM、RFID、指纹或真实门锁业务。
```

## 8 阶段 2 密码开锁

```text
使用 $smart-door-lock-graduation，以非阻塞纵向闭环实现 REQ-FUN-001 密码开锁：矩阵键盘扫描与消抖、掩码显示、确认和取消、输入超时、统一认证结果、LED 模拟门锁，以及 5 秒后自动上锁。开锁期间界面刷新和按键扫描必须继续工作。覆盖空输入、过短、过长、非法键、重复按键和超时边界。默认密码与配置集中管理，并记录临时默认密码的安全限制。
```

## 9 阶段 3 RTC 和 EEPROM

```text
使用 $smart-door-lock-graduation 实现 DS3231 与 AT24C02 阶段。编码前先冻结存储布局。实现 BCD 与时间有效性检查、AT24C02 跨页拆分、写周期的有界等待、带魔数/版本/CRC 的配置、默认值和损坏恢复。所有数据必须装入 256 字节，不得把开锁日志写入 AT24C02。为 CRC、序列化、损坏数据、版本不匹配和计时逻辑增加可在 PC 运行的测试，并提供 20 次断电恢复的台架测试；明确哪些结论必须实际断电才能验证。
```

## 10 阶段 4 RFID

```text
使用 $smart-door-lock-graduation 实现阶段 4。先验证 RC522 的 SPI、引脚和版本寄存器，再实现带超时的 UID 读取、授权卡查找、重复检测、添加与删除，以及统一认证结果。不要把 UID 当作秘密，也不要声称具有密码学安全性。测试模块缺失、超时、异常卡数据、重复添加、列表已满和未授权卡；同步更新存储容量与需求追踪。
```

## 11 阶段 5 指纹

```text
使用 $smart-door-lock-graduation，根据仓库内实际 AS608 协议资料实现阶段 5。结合我的实物证据核对包格式、地址、校验和、响应码、波特率和模板容量。实现搜索、两次采集录入、删除、模板 ID 到用户 ID 的映射、有界重试与超时，以及模块断开后的恢复；主循环必须保持响应。串口日志不得泄露不必要的敏感信息。提供已录入、未录入、接触不良、超时、拔除、重复、库满和断电后的台架测试矩阵。
```

## 12 阶段 6 管理员与安全策略

```text
使用 $smart-door-lock-graduation 实现阶段 6。先定义管理员认证边界和菜单状态机，再实现密码/卡片/指纹管理、连续失败计数、临时锁定、蜂鸣器和状态反馈、管理员会话超时及看门狗。失败或畸形的外设响应绝不能授权开锁。检查整数边界、状态转换、复位行为、日志中的秘密信息和 EEPROM 磨损；增加权限绕过、连续失败、锁定期间复位、菜单超时和配置损坏测试。
```

## 13 阶段 7 真实门锁

```text
使用 $smart-door-lock-graduation 推进阶段 7，但必须按安全门禁处理。先审计已记录的 MOSFET/继电器电路、有效电平、续流保护、电源、共地和实测锁电流；只有这些事实确认后，才实现可配置极性和最大动作时间。分别给出“GPIO 接 LED”“驱动器不接锁”“驱动器接真实锁”三套测试。定义电压跌落、MCU 复位、OLED 闪屏、RFID/指纹掉线、器件温升和连续 100 次动作的通过/失败证据。绝不能建议 GPIO 直接接 12 V 锁。
```

## 15 合并前代码评审

```text
使用 $smart-door-lock-graduation，对当前差异按对应需求和验收标准做代码评审。优先查找授权逻辑、门锁安全状态、超时、Tick 回绕、中断与主循环共享、缓冲区长度、EEPROM 越界和磨损、协议校验、错误恢复、生成代码边界及资源占用问题。引用精确文件和行号，运行相关检查，区分阻塞缺陷和改进建议；如果没有可执行缺陷也要明确说明。除非我要求修复，否则不要改文件。
```

## 16 测试证据与阶段门禁

```text
使用 $smart-door-lock-graduation 审计[里程碑]是否完成。将每条验收标准追踪到代码，并标记为 AUTO-PASS、BENCH-PASS、REVIEW-PASS、PENDING-HW 或 BLOCKED。运行当前环境可执行的全部相关检查。创建或更新简洁测试报告，包含工具链版本、固件提交、硬件版本、接线/配置、步骤、期望、实际结果、重复次数、日志/测量、缺陷和结论。决定性硬件证据仍为 PENDING-HW 时，不得通过门禁。
```

## 17 发布版本

```text
使用 $smart-door-lock-graduation 为已批准范围准备[vX.Y.Z]发布。审计完成定义，运行回归，检查 Debug/Release、警告、Flash/RAM/Map、配置与存储版本、固件版本、已知限制和可重复构建。已有固件产物时生成发布说明、产物清单和哈希。除非我明确要求，不要创建或推送远程 Tag。在声称“可发布”前列出所有 PENDING-HW 和 BLOCKED 项。
```

## 18 建立论文证据矩阵

```text
使用 $smart-door-lock-graduation，根据仓库建立论文证据矩阵。对每个拟写结论关联需求、设计章节、源码、测试用例、真实证据、所需图表，并标记为“已实现且验证、已实现未充分验证、仅预留接口、未来工作”。指出表述过强的结论，列出缺失测量及支持它所需的最小实验。此时先不要写最终论文正文。
```

## 19 撰写论文某一章

```text
使用 $smart-door-lock-graduation，根据已验证的仓库证据和我提供的学校模板/规范撰写[章节名称]。先给出“论点—证据”提纲并列出缺少的引用或测量；再使用正式中文解释设计选择和权衡，只引用真实存在的图、表、源码和测试数据。明确区分已实现功能、仅预留接口和未来工作。不得编造参考文献、截图、性能数字、可靠性结果或创新点。
```


## 21 在新聊天继续
